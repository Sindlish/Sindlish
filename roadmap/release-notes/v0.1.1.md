# Sindlish v0.1.1 — Closures, Bug Sweep, and a Unified Error Philosophy

**Released:** 2026-09-10 · **Commits:** 129 since v0.1.0 · **Tests:** 522 passing

---

> *Six months ago, Sindlish couldn't do closures. It had a broken MRO, a
> non-ASCII mojibake problem, a dead print pipeline nobody noticed, and a
> consistency issue with how every arithmetic operator handled failure. This
> release fixes all of it — and more importantly, establishes the principles
> that will guide every future release.*

---

## What's new

### Closures and `bahari` (nonlocal)

Nested functions can now capture variables from their enclosing scope. This is
the feature that makes Sindlish feel like a real language instead of a fancy
calculator.

```sindlish
kaam make_counter() {
    adad count = 0
    kaam increment() {
        count = count + 1
        wapas count
    }
    wapas increment
}

kaam counter = make_counter()
likh(counter())    # 1
likh(counter())    # 2
likh(counter())    # 3
```

The mechanism: captured variables become `Cell` objects — shared boxes that both
the outer and inner functions hold a reference to. When the inner function writes
to a captured variable, it writes through the cell. When the outer function reads
it later, it sees the change. The `bahari` keyword explicitly marks a name as
belonging to the nearest enclosing function's scope:

```sindlish
kaam outer() {
    adad x = 10
    kaam inner() {
        bahari x = 20    # writes to outer's x via cell
    }
    inner()
    likh(x)    # 20
}
```

Reading from an outer scope doesn't require `bahari` — capture is automatic.
Writing to an outer variable *without* `bahari` raises a helpful error. This is
a deliberate design choice: reads are safe, writes are explicit.

### `silsilo` replaces `range`

The `silsilo` (serial/sequence) type is now a lazy range object with O(1)
`lambi` (length), indexing, and truthiness. No list materialization. This means
`har i mein silsilo(1000000)` doesn't allocate a million-element list.

```sindlish
silsilo(5)          # [0, 1, 2, 3, 4]
silsilo(1, 10)      # [1, 2, ... 9]
silsilo(1, 10, 2)   # [1, 3, 5, 7, 9]
```

### Set intersection renamed to `mushtarak`

`milap` was retired after consulting the Sindhi Language Authority dictionaries.
Both `ٻڌي` ("bade") and `ميلاپ` ("milap") are listed as words for *union*, but
the official intersection terms are cutting/crossing words. `mushtarak`
(مشترک, "shared/common", familiar from Urdu math education) is now the
intersection method name. `milap` has no alias.

```sindlish
majmuo a = {1, 2, 3}
majmuo b = {2, 3, 4}
likh(a.mushtarak(b))    # {2, 3}
```

### `match` keyword reserved

The `match` keyword is now accepted by the lexer. The parser will reject it with
a clean message ("match abhi available natho") until the full pattern-matching
feature is implemented. This prevents confusing "unknown identifier" errors for
people who read ahead in the docs.

## The bug sweep

Between v0.1.0 and v0.1.1, a systematic audit of every stage of the pipeline
found and fixed **16 bugs** across the lexer, parser, resolver, compiler, VM,
and object model. Every fix has a regression test.

### Critical

| Bug | What went wrong | Fix |
|---|---|---|
| Functions couldn't read top-level variables | `LOAD_GLOBAL` was never emitted for program-level names | Unified storage: program variables live in globals, function locals use slots |
| Non-ASCII string literals were mangled | `codecs.decode("unicode_escape")` turned `"سلام"` into mojibake | Hand-rolled `_unescape()` that only touches backslash pairs |
| Default parameters stored AST nodes, not values | Defaults were compiled at call time instead of definition time | `MAKE_FUNCTION` opcode now evaluates and stores defaults on `SdFunction.defaults` |
| Dict/set used as a condition crashed the VM | `JUMP_IF_FALSE` read `.value` blindly | New `sd_truthy()` helper handles every object kind |
| Typed assignment from Result-returning ops always failed | Type checks didn't unwrap `Ok(...)` wrappers | `_check_type` now unwraps before comparing; error Results still propagate |
| `aalmi` (global) crashed the compiler | Missing `compile_GlobalNode` + a `type(node).name` → `__name__` typo | Added handler, fixed the attribute access |

### Silent wrong behavior

| Bug | What went wrong | Fix |
|---|---|---|
| Call-site `*args`/`**kwargs` silently dropped | Markers were parsed but not emitted | Marker-prefixed operands (`StarArgsMarker`/`KwargsDictMarker`); VM expands them |
| Keyword detection sniffed string arguments | Kwarg names traveled as plain `SdString` | `KwargMarker(SdString)` wraps them as a distinct type |
| No short-circuit evaluation | `aen`/`ya` always evaluated both sides | `JUMP_IF_FALSE_OR_POP` / `JUMP_IF_TRUE_OR_POP` opcodes skip the right operand when decided |
| `nah`/`aen`/`ya` on numbers did bitwise ops | Logical ops went through bitwise code paths | Truthiness-based for every type; `nah 5` → `koorh` |
| `lambi(lughat)` raised | `SdDict` wasn't in the length handler | Added `SdDict.pairs` support |
| Redeclared variable failed runtime check | Stale metadata from earlier declaration | Explicit redeclaration overwrites slot metadata (last-wins) |
| Functions-as-values bound None | Function names resolved through locals, not globals | Names resolve through globals so `g = foo` binds the real `SdFunction` |
| `jistain x / y { }` never terminated | Division Result didn't auto-unwrap in conditions | `sd_truthy` unwraps `Ok(...)` Results before checking truth |

### Correctness / UX

| Bug | What went wrong | Fix |
|---|---|---|
| `likh(sach)` printed "such" | Keyword was `sach`, not `such` | Fixed spelling |
| Chained comparisons crashed cryptically | Parser didn't handle `a < b < c` | Clean rejection message with suggestion to use `aen` |
| Unclosed block accepted at EOF | No block-level EOF check | `"Block band natho thayo"` error |
| Unhashable element in set/dict leaked raw TypeError | No guard on element hashing | `BUILD_SET`/`BUILD_DICT` map it to `QisamJeGhalti` |
| Traceback lines were off-by-one | `frame.ip - 1` was missing in both paths | Fixed in `_build_traceback` and `SdResult.capture_traceback` |
| REPL consts/types unenforced | `STORE_GLOBAL` didn't carry metadata | Metadata now travels with the opcode; VM enforces const + type on program-level assignments |

## Unified error philosophy

### The principle

All six arithmetic operators (`+ - * ^ / %`) now always return a `Result`:

- **Success**: wrapped in `Ok`, automatically unwrapped at function returns,
  parameter binding, and conditions.
- **Failure** (type mismatch, divide-by-zero): wrapped in `Ghalti`, stays as a
  `Result` until a caller inspects it.

Ordering comparisons (`< <= > >=`) **raise** `QisamJeGhalti` on type mismatch.
Equality (`== !=`) is **total** — every pair of values can be compared, no
matter the types.

### The reasoning

This settles a design question that had been open since v0.1.0. The original
implementation was inconsistent: some operators raised, some returned Results,
some did bitwise operations. The rule now is:

- **Operations that produce a value** (arithmetic) → Result
- **Operations that test a relationship** (ordering) → raise
- **Operations that answer a question** (equality) → total, never fails

This means `10 / 0` returns `Ghalti`, `10 + "hi"` returns `Ghalti`, but
`"hello" == 42` returns `koorh`. No surprises.

### Strict consumption

Using a `Ghalti` in a further operation or condition raises immediately. This
prevents silent error accumulation:

```sindlish
adad x = 10 / 0    # x is Ghalti (ZeroVindJeGhalti)
adad y = x + 1      # ← raises! Ghalti can't be used in arithmetic
```

The error surfaces at the exact point where you tried to use the bad value —
not three lines later in some mysterious stack trace.

## Performance

### VM dispatch

The dispatch loop was inlined and loop-invariant code was hoisted. Frame
re-synchronization now only happens on call/return boundaries, not every
instruction. `_pop_pair` unwraps operands in one step.

### O(1) constant pool deduplication

Constants are now interned by value (integer keys) instead of linear scan.
Programs with repeated strings or numbers see a measurable improvement.

### Precomputed CallPlan metadata

Function call metadata (parameter names, arity, defaults) is computed once at
definition time and stored on `SdFunction`. The fast path for simple calls (no
starargs, no kwargs) skips all the overhead of the general binding algorithm.

### Benchmarks

A new benchmarking framework lives in `tools/bench/` with multiple drivers and
JSON/table reporting. Benchmarks run against Python's own interpreter for
comparison. The rule: every performance change must be justified by a benchmark,
not a feeling.

## Tooling

### `sindlish` CLI

The interpreter is now a proper installable package with a real CLI:

```bash
sindlish run script.sd      # execute a file
sindlish repl               # interactive REPL
sindlish eval "likh(2+2)"  # evaluate one expression
sindlish tokens script.sd   # dump token stream
sindlish ast script.sd      # dump AST
sindlish check script.sd    # validate syntax + semantics
sindlish docs               # offline documentation
```

### `Interpreter` facade

The `Interpreter` class in `interpreter/__init__.py` exposes the full pipeline:

```python
interp = Interpreter()
interp.run_source("adad x = 10")
# Or step by step:
tokens = interp.lex(source)
tree = interp.parse(tokens)
interp.resolve(tree)
bytecode = interp.compile(tree)
vm = interp.build_vm()
interp.check()    # validate without running
```

### Offline documentation

`sindlish docs` now works from a bundled text file — no internet required. The
file is included as package data, so it works whether installed via pip, running
from source, or inside a frozen PyInstaller binary.

### VS Code extension (0.1.1)

First public release of the extension:

- Syntax highlighting via TextMate grammar **auto-generated from the language's
  own keyword and builtin registries** — the grammar never drifts from the
  implementation
- Snippets for all keywords and collection methods
- LSP diagnostics via the new `sindlish check` mode

### Distribution

PyInstaller onedir builds for all three platforms, bundled with:
- Windows: Inno Setup installer (`installer.iss`)
- macOS: `.pkg` via `pkgbuild`
- Linux: `.deb` via `dpkg-deb`

The `install.sh` script handles source installs with a `uv` → `pipx` → `pip`
fallback chain.

## Dead weight removed

### The dead print pipeline

`TokenType.LIKH`, `parse_print()`, `PrintNode`, and `PRINT_ITEM` were all
dead code — `"likh"` was never in the `KEYWORDS` dict, so the lexer always
emitted `IDENTIFIER('likh')`. Printing worked as a builtin call the entire time.
The whole dedicated statement path was deleted.

### Vestigial machinery

`SdShey._ref_count` (removed during the move to Python's GC), unused
`Environment.global_names`/`nonlocal_names` fields, the duplicate
`JUMP_IF_FALSE` dispatch entry, and the unused `DUP_TOP` opcode — all removed.

## Documentation

### The mdBook

*Sindlish Internals — A Cozy Field Guide* is now the single canonical docs
source. It covers the entire pipeline from characters to bytecode, written in
a conversational tone with Mermaid diagrams, worked examples, and appendices
for the AST, grammar, distribution, and extension.

Old docs (the `docs/` submodule and `developer-docs/`) were removed.

### Code documentation

The `Interpreter` facade and CLI functions have docstrings. Internal methods
don't — by convention, the code is self-documenting through naming and
structure. The rule: if you can't understand what a function does from its name
and its neighbors, the function is too complex.

## What I learned building this

The bug sweep was humbling. Some of these bugs (the non-ASCII mojibake, the
dead print pipeline) had been there since the beginning and nobody noticed
because the test coverage happened to avoid the triggering paths. Others (the
short-circuit evaluation, the bitwise logical ops) were fundamental design
problems that only surfaced when someone wrote `nah 5` and got `0` instead of
`koorh`.

The MRO bugs were the most educational. I wrote C3 linearization from a paper,
thought it worked, tested it with simple cases — and then a book chapter forced
me to walk a diamond by hand and realize the output was wrong. The algorithm
was correct; my implementation had two independent bugs that cancelled each
other out in the common case but produced silently wrong results for complex
hierarchies. Both are now fixed with full regression coverage.

The error philosophy unification (issue #33) was the hardest *design* decision,
not the hardest code change. "Should all arithmetic return Results?" sounds
obvious until you realize it means `1 + 2` now returns an `Ok(3)` that must be
unwrapped before anyone can use it. The answer: automatic unwrapping at
boundaries (function returns, parameter binding, conditions) means the `Ok`
layer is invisible in practice — you only see `Result` when you want to.
