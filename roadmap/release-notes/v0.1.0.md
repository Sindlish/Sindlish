## What this is

Sindlish is a high-level programming language where every keyword is a Sindhi
word. It compiles to bytecode and runs on a stack-based virtual machine. This is
not a toy transpiler or a renamed Python — it is a five-stage pipeline from
characters to execution, built from scratch with its own error philosophy, its
own typing rules, and its own object model.

The goal: remove the English-language barrier for millions of Sindhi/Urdu
speakers who think about programming but hit a wall when every keyword, error
message, and documentation page is in a language they didn't grow up speaking.

---

## The pipeline

```
Source code → Lexer → Parser → Resolver → Compiler → VM → Execution
```

Each stage has a single job and a clean boundary. The lexer (`lexer.py`, ~328
lines) turns characters into tokens. The parser (`parser.py`, ~1,278 lines of
recursive descent) turns tokens into an AST. The resolver (`resolver.py`, ~834
lines) handles name resolution, slot allocation, and static type checks. The
compiler (`compiler.py`, ~787 lines) walks the AST and emits bytecode. The VM
(`vm.py`, ~1,457 lines) is a stack machine that executes it.

Every file is under 1,500 lines. The whole language is under 7,000 lines of
Python. That's intentional — Sindlish is small enough for one person to hold in
their head.

## What's in it

### Types and variables

```sindlish
adad x = 10          # integer
dahai y = 3.14       # float
lafz s = "hello"     # string
faislo b = sach       # boolean (sach/koorh)
khali n               # null
pakko lafz NAME = "Sindlish"  # constant
```

Six declaration styles (explicit type, inferred, colon annotation, etc.) and
typed collections:

```sindlish
fehrist[adad] nums = [1, 2, 3]
lughat[lafz, adad] scores = {"Ali": 90, "Sara": 85}
majmuo[lafz] names = {"Ali", "Sara"}
```

### Operators

```sindlish
x + y  x - y  x * y  x / y  x % y  x ^ y    # arithmetic
x == y  x != y  x < y  x > y  x <= y  x >= y  # comparison
aen  ya  nah                                    # logical (and/or/not)
```

Arithmetic division (`/`) and modulo (`%`) return a `Result` — they never
crash. The `^` operator is exponentiation and it's right-associative (unlike
Python, where `**` is).

### Control flow

```sindlish
agar x > 5 {
    likh("big")
} yawari x > 2 {
    likh("medium")
} warna {
    likh("small")
}

jistain x < 10 {
    likh(x)
    x = x + 1
}

har i mein silsilo(5) {
    likh(i)
}

tor     # break
jari    # continue
```

### Functions

```sindlish
kaam add(adad a, adad b) {
    wapas a + b
}

kaam greet(lafz naam = "dunya") {
    likh("Salam " + naam + "!")
}

# Variadic args
kaam log(*args) {
    har item mein args {
        likh(item)
    }
}

# Call-site unpacking
fehrist nums = [1, 2, 3]
adad total = add(*nums)
```

### The Result system

This is the part I'm most proud of. Sindlish doesn't use try/catch. Instead,
every operation that can fail returns a `Result` — a value that's either
successful (`Ok`) or contains an error (`Ghalti`). You can propagate, inspect,
or handle results explicitly:

```sindlish
kaam divide(adad a, adad b) {
    wapas a / b    # returns Result
}

dahai result = divide(10, 2)?     # ? = unwrap Ok, or propagate Ghalti
dahai safe = divide(10, 0)?.bachao(0.0)   # fallback value on failure
adad strict = divide(10, 0)!!     # !! = panic on failure with traceback
```

The `?` operator is soft propagation: if the inner expression is a `Ghalti`,
it automatically becomes the return value of the enclosing function. If it's an
`Ok`, the value is unwrapped. This means error propagation is invisible — you
just use `?` and the error travels up the call stack until someone handles it.

### Error taxonomy

Eight error classes, all named in Sindhi:

| Sindlish | English | Meaning |
|---|---|---|
| `LikhaiJeGhalti` | Writing error | Syntax error |
| `NaleJeGhalti` | Name error | Undefined variable |
| `QisamJeGhalti` | Type error | Wrong type |
| `HalndeVaktGhalti` | Runtime error | Something broke during execution |
| `ZeroVindJeGhalti` | Zero error | Division by zero |
| `IndexJeGhalti` | Index error | Out of bounds |
| `TarteebJeGhalti` | Structure error | Wrong structure |
| `MatalabJeGhalti` | Meaning error | Wrong argument count |

Every error includes a line, column, and a caret snippet pointing at exactly
what went wrong.

### Builtins

```sindlish
likh("hello", "world")     # print (space-joined)
puch("? ")                 # input
lambi("hello")             # length (5)
silsilo(1, 10)             # range [1, 2, ... 9]
qisam(42)                  # type-of ("adad")
adad("42")                 # type cast
dahai("3.14")
lafz(42)
faislo(1)                  # → sach
fehrist([1, 2, 3])         # list constructor
```

### ~35 collection methods

```sindlish
fehrist l = [1, 2, 3]
l.wadha(4)              # append
l.wajh(0, 0)            # insert at index 0
l.kadh()                # pop last
l.hata(2)               # remove value
l.tarteeb()             # sort
l.ulto()                # reverse
l.nakal()               # copy
l.garn(2)               # count occurrences
l.index(3)              # find index
l.saf()                 # clear

lughat d = {"a": 1}
d.resultat("a")         # get
d.cabeyon()             # keys
d.raqamon()             # values
d.syon()                # items
d.kadh("a")             # pop

majmuo s = {1, 2, 3}
s.addkar(4)             # add
s.mushtarak({2, 3})     # intersection
s.bade({3, 4})          # union
s.farq({3})             # difference
```

## Tooling

### CLI

```bash
python main.py run script.sd      # execute a file
python main.py repl               # interactive REPL
python main.py eval "likh(2+2)"  # evaluate one expression
python main.py tokens script.sd   # dump token stream
python main.py ast script.sd      # dump AST
python main.py check script.sd    # validate syntax + semantics
python main.py docs               # offline documentation
python main.py --version          # 0.1.0
```

### REPL

Syntax highlighting, tab completion for keywords and builtins, error recovery
(errors don't crash the REPL).

### VS Code extension

Syntax highlighting via a TextMate grammar generated from the language's own
keyword registries (so it never drifts from the implementation), plus snippets
for all keywords and collection methods.

### Installers

One-file installers for Windows (Inno Setup), macOS (pkgbuild), and Linux
(dpkg-deb). The `install.sh` script handles source installs with `uv`/`pipx`/`pip`.

## What's not in it (and why)

| Feature | Status | Why |
|---|---|---|
| Closures / `bahari` | Not yet | Requires cell/slot machinery; planned for next release |
| `match` statement | Reserved | Keyword reserved, parser not built yet |
| Classes / `jamaat` | Dormant | MRO infrastructure exists; user-facing classes need more type system work |
| Module system / `shamil` | Not yet | Single-file programs only today |
| File I/O | Not yet | Every program runs in memory |
| Slicing (`s[1:3]`) | Not yet | Indexing works; slicing syntax not implemented |
| Comprehensions | Not yet | Planned alongside collection ergonomics |
| F-strings | Not yet | String concatenation works; interpolation syntax not designed |

These aren't gaps in ambition — they're deliberate sequencing. The core
pipeline needed to be solid before layering complexity on top. It is now.

## The test suite

**236 tests** across 25 pytest files, organized one-per-feature. Every test runs
the full five-stage pipeline (no mocks, no shortcuts). The test harness in
`conftest.py` is 100 lines and every test uses it.

The rule: if you can't write a test for it, it doesn't exist in Sindlish.

## What I learned building this

The error system was the hardest part. Not the technical implementation — the
*design*. "Should division crash or return a value?" sounds like a technical
question but it's actually a philosophical one. Python crashes. Rust wraps in
`Result`. Sindlish does something neither does: the *boundary* between Results
and plain values is explicit. `Ok` values are unwrapped automatically at
function returns, parameter binding, and conditions. `Ghalti` stays as a
`Result` all the way to a caller who inspects it. This means you can write code
that never sees the word "Result" until you want to, and then you see it
everywhere.

The other thing: Sindhi speakers will read `likh("Salam")` the way an English
speaker reads `print("Hello")`. The whole point is that nothing feels foreign
anymore. That's not a language feature. That's the reason the language exists.
